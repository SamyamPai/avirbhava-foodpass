# Avirbhava'26 FoodPass – Email QR Setup

This version keeps the existing admin/scanner/veg/non-veg/year/section functionality and adds college-email QR delivery.

## What changed

- Registration now requires a college email ending exactly in `@sahyadri.edu.in`.
- `students.email` stores the email.
- `students.qr_email_sent_at` records the last successful QR email send.
- Admin approval automatically sends the approved student's unique QR by email when an email exists.
- Existing approved registrations are not deleted or changed. In the admin dashboard, click **Email** on a student to add/update their college email; if they are already approved, saving the email automatically sends their QR.
- Approved students also have a **Send QR** button for manual resend.
- The QR token remains the existing unique UUID generated by the database. The email does not create a new token, so the scanner continues to work exactly as before.

## 1. Run the SQL migration

Open Supabase Dashboard → SQL Editor and run:

`supabase/EMAIL_QR_MIGRATION.sql`

This adds only two columns to the existing `students` table:

- `email`
- `qr_email_sent_at`

It also updates the registration/admin RPCs and adds `admin_update_student_email`.

## 2. Resend

Create a free Resend account and create an API key.

The current Resend free plan is 3,000 emails/month with a 100-email/day limit. Therefore, 700 emails cannot all be sent on the same day on the free plan; if you need all 700 immediately, use a paid plan or another mail provider.

For real student delivery, configure a sending domain you control and verify its DNS records in Resend. Do not try to send as `@sahyadri.edu.in` unless you are authorized to control/verify that domain.

## 3. Add Edge Function secrets

In Supabase Dashboard → Edge Functions → Secrets, add:

- `RESEND_API_KEY` = your Resend API key
- `RESEND_FROM_EMAIL` = e.g. `Avirbhava'26 <noreply@your-verified-domain.com>`

Supabase automatically provides `SUPABASE_URL` and the service-role/secret credentials to Edge Functions. Never put the service-role key in the React/Vercel `.env`.

## 4. Deploy the Edge Function

The function is:

`supabase/functions/send-foodpass-email/index.ts`

CLI:

```text
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy send-foodpass-email --use-api
```

The Supabase Dashboard can also deploy Edge Functions directly from the Edge Functions editor.

## 5. Frontend environment

Keep the normal Vercel variables only:

```text
VITE_SUPABASE_URL=...
VITE_SUPABASE_KEY=...
```

Do NOT add `RESEND_API_KEY` to Vercel and do NOT prefix it with `VITE_`.

## 6. Test safely

1. Register one test student with a real `@sahyadri.edu.in` address.
2. Approve the student in Admin.
3. The QR email should be sent automatically.
4. Confirm the email contains the QR attachment.
5. Scan that QR with the scanner.
6. Confirm the scan is `VALID` and then a second scan is `ALREADY_USED`.
7. Test an invalid email such as `test@gmail.com` — registration should be rejected.

## Important

The email service does not replace the existing status/scanner flow. The current QR remains in Supabase and the scanner continues to redeem the same token atomically.
